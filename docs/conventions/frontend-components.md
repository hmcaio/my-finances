# Shared components (`src/components`)

Read when building a list page, an error banner, a confirmation, a month field or pagination. Use these instead of re-inlining the markup; each replaced copy-pasted code from every settings/list page. The responsive set (`ResponsiveTable`, `ResponsiveDialog`, `ResponsiveFilterBar`) is in [frontend-responsive.md](frontend-responsive.md).

- `ErrorAlert`: dismissible error banner; renders nothing for a `null` message. `AccountDetailPage`'s banner is intentionally _not_ this (non-dismissible, different spacing).
- `InlineEditActions`: the pencil -> check/X trio for an inline-edit table row; `editLabel` is required (labels differ per page), `saveLabel` defaults to "Save", `saving` disables save/cancel. Its state is `useInlineEdit(emptyDraft)` (`hooks/`): `editingId`, `draft`/`setDraft`, `start(id, draft)` and `cancel()` (clears the row and resets the draft; call it after a successful save too, a failed save keeps the row open). `saving` is `useAction(setError).pending` ([frontend-data-loading.md](frontend-data-loading.md)).
- `ConfirmDialog`: destructive-action confirmation (delete/close/dismiss). A dialog containing a form is not a fit; keep those custom.
- `PaginationControls`: Previous/"Page X of Y"/Next for a `PagedModel`. `onPageChange` takes a functional updater (pass `setPage` directly) so rapid clicks stay correct against React's latest state; its `sx` overrides the default embedded-list spacing for standalone pages.
- `DataTableBody`: the `<TableBody>` for every list table: skeleton rows while loading, a "Could not load data (...)" row with Retry if the first fetch failed, real rows (fade-in) otherwise. Takes `state` (a `LoadState` from `useQueryState(query)`, or several merged with `combineLoadState`). `columns` must match the header; set `actionsColumn` when the last column holds icon buttons, so placeholder rows match the real row height.
- `AddFormDialog` (`feedback/`) + `useAddDialog` (`hooks/`): the "Add" dialog of a settings-style page (Institutions, Categories, Vehicles, Budgets, Recurring templates). The dialog shell (title, error banner, `FormGrid`, Cancel/Add) is shared, the fields stay in the page; `useAddDialog(emptyDraft).close` resets the draft, so Cancel, Esc and a saved add all reopen empty (a failed save keeps the draft). A new page-level add dialog uses both rather than its own `useState` per field. A form that owns its state (`AccountCreateForm`, `InvestmentProductForm`) is not wrapped in it.
- `ReadOnlyNameListPage` (`layout/`): the page for a fixed, name-only taxonomy with no add/rename/delete (payment methods, investment segments; ADR 0028). Pass already-translated `title`/`description`/`emptyText`, the query and a `displayName` (the `translateSeedName` call), so each page keeps its own i18n namespace. A taxonomy with real editing (Categories, Institutions, Vehicles) or nesting (investment categories) is not a fit.
- `LoadFailedNotice`: inline "could not load" text + Retry; for non-table blocks (the `BudgetsPage` report).
- `MonthPicker` (`inputs/`): the `<input type="month">` field shared by every month-scoped view (`BudgetsPage`'s report month, `AllocationPlanEditor`'s effective-from, F026's `FiiPage`). `clampToCurrentMonth` (default off) clamps a selection past the current month back to it and caps the native picker with `max`: set it only where there's no future data to show (the FII page); omit it where a future month is meaningful (a plan's effective-from, which can be set ahead; a budget report month, which isn't clamped either).
- `MonthNavigator` (`inputs/`, F037): `‹ month ›` (previous/next `IconButton`s around `MonthPicker`, unclamped so a future month is reachable) for a view that steps through months, `value`/`onChange` in `YYYY-MM`; `shiftMonth`/`monthRange` in `utils/localDate` do the month arithmetic without `Date`/UTC conversion. The Ledger keeps its month in the URL, the account page's embed in local state.
- **Layout primitives** (`components/layout/`, issue #259) for the markup every page repeated; use them instead of re-inlining the `sx`:
  - `Layout` owns the page's one `main` landmark, `id="main-content"` and `tabIndex={-1}`, the target of its "Skip to content" link (F040): a page renders no `main` of its own.
  - `PageContainer`: the root of a routed page (`py: { xs: 2, sm: 4 }`).
  - `PageHeader`: the title row of a list page, `title` as the `h1` (h4 style) with the actions (an "Add" button, its menu) as children; the row wraps (`flexWrap: 'wrap'`) so an action drops under the title on a phone instead of squeezing it; `sx` merges after the base. A page with a title and no action keeps a plain `Typography variant="h4" component="h1"`.
  - `PageSection`: an outlined `Paper` with the section padding (`SECTION_PADDING`, 16px on a phone, 24px from `sm`); `sx` adds `mb: 3` or `maxWidth: 480`.
  - `FormDialogContent` (`feedback/`): `DialogContent` plus the `pt: 1` wrapper that keeps the first field's floating label from being clipped; the error banner and `FormGrid` go inside it.
  - `layout/layoutSx.ts` constants: `WRAP_ANYWHERE` (long text wraps instead of widening its container; spread to combine: `{ ...WRAP_ANYWHERE, mb: 2 }`), `SELECT_MIN_WIDTH` (a compact `Select`), `FORM_GRID_FULL_ROW` (a `FormGrid` child spanning every column), `SECTION_PADDING`.
  - A one-off spacing prop (`mb: 3`, `pt: 1`) or a `Paper` with a single padding value stays inline `sx`: a primitive needs 4+ identical uses and a name that says more than the props. Tests assert responsive `sx` through `emittedCss`/`emotionClass` (`src/test/utils/emittedCss.ts`), since jsdom does not evaluate `@media`.
- `NotificationHost` (`providers/notifications/`, F040): the success toast, a MUI `Snackbar` + `Alert severity="success" role="status"` that hides after 4 s and is rendered once by `Layout` (a jsdom test that renders `Layout` needs no extra wrapper: the store is module-level and `src/test/setup.ts` resets it after each test). It sits at the bottom start from `sm` up (beside the permanent drawer from `lg`, `DRAWER_WIDTH` in `layoutSx.ts`, so it never covers a nav item) and at the top on a phone, over the app bar and with `pointer-events: none`, so it never covers a dialog's bottom actions or the page's "Add" button; a second message replaces the first. Do not render a `Snackbar` per page: set `meta.successMessage` on the mutation ([frontend-data-loading.md](frontend-data-loading.md)); `publish(message)` from `notificationStore` is for the query client, not for components.
- `LedgerTable` (`features/ledger/components`, F037): the one list of transactions and transfers, shared by `LedgerPage` and the read-only `AccountLedger` embed (omit `onEdit`/`onDelete` for read-only, pass `embedded` inside an outlined section). A row is told apart by icon, sign and colour from `ledgerEntryStyle` (never colour alone; theme tokens only), and its name cells come from `useLedgerLookups`, which also supplies the combined load state. A new view of ledger rows reuses it instead of re-declaring columns.
