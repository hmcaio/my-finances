# Accounts, net worth and investment balances (backend)

Read when code reads an account's opening balance, computes a balance or net worth as of a date, queries investment snapshots, or adds a table that references accounts.

- **`Account.getOpeningBalance()`/`getOpeningBalanceDate()` are `null` for an `INVESTMENT` account** (ADR 0012, backed by a DB `CHECK`), so any code that reads them branches on `getType()` first. `AccountBalanceQuery` does: its `INVESTMENT` branch sums the latest snapshots of the `InvestmentHolding`s pointing at that account (`LatestInvestmentSnapshotQuery`, F022/ADR 0020). `TransactionService`/`RecurringTemplateService` reject such an account with their own package's `AccountTypeNotAllowedException`. Building an `INVESTMENT` account in a test: [backend-testing.md](backend-testing.md).
- **`NetWorthQuery` counts an account only between its `openingBalanceDate` and its `closedDate` (exclusive)**, per date, never "every non-closed account" (that would drop a closed account from every past month). An `INVESTMENT` account has no opening date, so it always counts and is `0` until its first snapshot. Sums are as-of, computed on read from `AccountBalanceQuery`; nothing is stored. `trend()` computes every non-investment account's balance across the sampled dates in one forward pass (ledger events loaded once, sorted, walked with a per-account cursor) rather than calling `AccountBalanceQuery.balanceAsOf` per date: that re-reads an account's whole history every time and was O(dates x accounts x transactions) (issue #94). An `INVESTMENT` account still goes through `balanceAsOf` per date since its snapshot history is small by construction; it isn't the bottleneck, so it keeps that path unless there's a reason.
- **`LocalDate.MAX`/`MIN` never reach a repository query**: Postgres can't represent it and the request fails with a 500. "The latest snapshot regardless of date" is `LatestInvestmentSnapshotQuery.latestOf(holdingId)` / `latestByHolding()` (in-memory reduce over `findByHoldingId`/`findAll`), not `findAllOnOrBefore(LocalDate.MAX)`.
- **Deleting an account**: `AccountService.delete()` hard-deletes only an account nothing references (409 `AccountHasHistoryException` otherwise, ADR 0017), via the `AccountUsageChecker` port (`infrastructure/account/RealAccountUsageChecker`: transactions, transfers on either side, templates incl. inactive, investment holdings incl. closed; moved from `investment_products` to `investment_holdings` by F022/ADR 0020, since the product itself no longer has an `account_id`). **A new table with an FK to `accounts` must be added to that checker** (and `RealAccountUsageCheckerTest`), or deleting an account it references surfaces as a 500 from the FK instead of the 409.
