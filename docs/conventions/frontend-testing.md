# Frontend testing specifics (Vitest, RTL, MSW)

Read when writing or debugging a Vitest test, an MSW handler or a seed fixture. Playwright: [frontend-e2e.md](frontend-e2e.md).

- Vitest is configured entirely through `vite.config.ts`'s `test` key (`environment: 'jsdom'`, `setupFiles: ['src/test/setup.ts']`): there is no `vitest.config.ts`. `globals` is off, so `src/test/setup.ts` calls React Testing Library's `cleanup()` itself.
- Test files are colocated (`*.test.ts` / `*.test.tsx`) and query with accessibility-first RTL queries (`getByRole`, `getByLabelText`), not test IDs.
- **MSW**: one handler file per aggregate in `src/mocks/handlers/<aggregate>.ts` (mirroring the `src/api` areas), combined in `src/mocks/handlers.ts`, served by `src/mocks/server.ts` and started/reset/closed by `src/test/setup.ts`: every test gets MSW automatically. Because every successful write refetches the active queries, default handlers are backed by an in-memory `createStore(seed)` (`src/mocks/store.ts`, restored by `resetStores()` after each test): a POST/PATCH/DELETE changes what the next GET returns, so a handler that only echoed the request would let the refetch bring the seed back over a just-created row. Per-test overrides use `server.use(...)`; to inspect a request body and keep the stateful behaviour, read `await request.clone().json()` and return nothing so the default handler runs. Add a handler for every new endpoint, plus a `409` variant where it can conflict.
- **A new seeded row added to a shared fixture array is visible to every page that lists it**, so a page's exact-count/exact-list assertion elsewhere breaks the moment the row is added (F024's `seedFuelCategory` would have broken `CategoriesPage.test.tsx`'s "lists each type" count). A row only a few tests need stays out of the default seed array (e.g. `categories.ts`'s `seedCategories`) and is exported standalone instead; a test that needs it overrides the handler with `server.use(http.get(url, () => HttpResponse.json([...seed, extraRow])))`.
- **`renderWithQueryClient` / `renderHookWithQueryClient`** (`src/test/renderWithQueryClient.tsx`) replace RTL's `render`/`renderHook` for anything using a `<area>Queries` hook (`renderWithRouter` already includes it): a fresh client per test with the app's mutation-invalidation rules, `retry: false` and `gcTime: 0`. Pass the same `client` to two hook renders to test cache reuse across mounts (and use `createQueryClient()` there, since `gcTime: 0` drops the cache on unmount). Hook tests go through MSW, not mocked API modules (see `src/api/*Queries.test.tsx`); the cache rules (shared-key dedup, invalidation after success, none after failure) are covered in `categoriesQueries.test.tsx`.
- `App.test.tsx` renders the real `BrowserRouter`, which reads the jsdom URL that a previous test's navigation leaves behind: reset it with `window.history.pushState({}, '', '/')` in `beforeEach`.
- `frontend/.env.test` sets `VITE_API_BASE_URL=/api` (relative, same-origin) so the Axios base URL and MSW's relative matching resolve against the same jsdom origin.
- **A `getByRole` query fails on elements behind an open MUI `Dialog`**, even elements nowhere near it: MUI marks the rest of the page `aria-hidden` while a modal is open, and role-based queries (unlike `getByText`/`findByText`, which don't consult the accessibility tree) respect that. A table-scoping helper like `within(screen.getByRole('table'))` (`BudgetsPage.test.tsx`, `RecurringTemplatesPage.test.tsx`) throws immediately if called while the add/edit dialog is still open: `await waitFor(() => expect(screen.queryByRole('dialog')).not.toBeInTheDocument())` before such a query, not after it.
- **Test files have no Node types** (`@types/node` isn't a dependency), which is why `npm run build` is part of the test loop (`frontend/CLAUDE.md`). Pin an env var/timezone with `vi.stubEnv('TZ', ...)` and `vi.unstubAllEnvs()` in cleanup, and pin a non-UTC zone for any date/time test: CI runs in UTC, where a UTC-vs-local bug is invisible.
- Viewport faking (`setViewportWidth`): [frontend-responsive.md](frontend-responsive.md). Mock session state: [auth.md](auth.md). Logging assertions: [logging.md](logging.md). Locale in tests: [frontend-i18n.md](frontend-i18n.md).
