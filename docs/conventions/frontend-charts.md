# Charts (hand-drawn SVG)

Read when adding or changing a chart or donut.

No chart library: `ValueSeriesChart`, `InvestmentAllocationChart`, `NetWorthTrendChart`, (F023) the flat donuts `InvestmentSubcategoryAllocationChart`/`InvestmentAccountAllocationChart`, (F024) `FuelTimeSeriesChart` (a generic multi-series line chart: one series for km/L or spend/km, one per fuel type for price/liter, with a legend only when there's more than one) and (F026) `FiiNestedAllocationDonutChart` are all hand-drawn SVG.

- **Shared line-chart helpers live in `src/components/charts/`**: `chartMath.ts` (`niceStep`, `dayNumber`, `createYScale` for the nice axis bounds, gridline values and y mapping, `createDayScale` for the proportional date x mapping) and `ChartSvg.tsx` (`ChartSvg`, the fluid accessible svg frame at `CHART_WIDTH` x `CHART_HEIGHT`, and `YGrid`, the gridlines with value labels). `ValueSeriesChart`, `NetWorthTrendChart` and `FuelTimeSeriesChart` use them, so a new line chart reuses them instead of a fourth copy; margins, x-axis labels, series paths and tooltips stay in each chart because they differ.
- **A chart that should fill its container** (F039's goal timeline) measures it with `hooks/useElementWidth` (a `ResizeObserver`, `null` until measured and in jsdom) and passes `width`/`height`/`fillWidth` to `ChartSvg` and `width` to `YGrid`, so the viewBox matches the pixels and text and strokes keep their size; without that the frame is the fixed 640 by 260, scaled down and capped at 640 wide. The measuring box must be a stable wrapper that is mounted before the data loads (a hook inside a body that only renders once data arrives never attaches its ref). Test it with a stubbed `ResizeObserver` and an `act` around the reported width.
- **React Compiler lint rules bite in charts specifically**: no reassigning a `let` after render (compute running offsets with `reduce`/`slice`) and no `useMemo` over values the compiler can't preserve (compute plainly).
- **Reuse rule for a new donut**: one that doesn't need `InvestmentAllocationChart`'s drill-down reuses `features/investments/overview/lib/donutGeometry.ts` (the pure SVG-arc math) and `FlatAllocationDonutChart` (the shared flat donut+legend rendering) rather than a third hand-rolled copy. `InvestmentAllocationChart` itself keeps its own copy since it predates this split and its drill-down behavior/tests must stay untouched.
- **Deliberate exception**: `FiiNestedAllocationDonutChart` (F026's Actual/Planned two-ring charts, Addendum - Nested Allocation Charts) reuses only `donutGeometry.ts`'s `segmentPath`/`pointOnCircle`, not `FlatAllocationDonutChart`. That component is wired to `useInvestmentAllocation`'s money-total/`needsSnapshot` staleness shape and draws one ring, while the FII chart is percentage-only, draws two rings (inner = segment, outer = ticker) from two separate queries (`useFiiAllocation(basis, 'SEGMENT', month)`/`('TICKER', month)`) and shades each ticker arc as an opacity variant of its parent segment's color, so the two don't fit one component without branching it apart. `donutGeometry.ts`'s `segmentPath` takes optional `outerRadius`/`innerRadius` arguments (defaulting to the module's single-ring `RADIUS`/`INNER_RADIUS` constants) for exactly this reason: a second ring is a second radius band, not a second file. A two-ring chart's inner-ring slice width is the sum of its own outer-ring children's percentages, not any independently-rounded total, which keeps the two rings tiling with no seam at the boundary (see `FiiNestedAllocationDonutChart`'s own docblock).
- A chart legend item that is a clickable MUI `Button` (`InvestmentAllocationChart`'s category drill-down) needs `whiteSpace: 'normal'` in its `sx` (F021): `Button` defaults to `white-space: nowrap`, so a long label forces the row wider than a phone screen even inside an otherwise-`flexWrap` container. A plain (non-`Button`) legend line doesn't have this problem.
